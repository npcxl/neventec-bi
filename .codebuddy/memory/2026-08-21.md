## 当前阶段搭建进程（施工进程 Steps）
- **需求**: `getCurrentStageConstructProcess` 接口返回当前阶段搭建进程，渲染"施工进程" Steps（5步：办理进度手续/上传：搭建许可证/开口尺寸确认/灭火器安全检查/上传：灭火器图片）。
- **api.ts**: 接口真实路径为 `a/api/inspection/record/summary/getExhibitionProcess`（与 getExhibitionProcess 同路径），带 `exhibitionId` + `hallId` 参数。getCurrentStageConstructProcess(exhibitionId, hallId?, signal?)。调用处：selectedHallId==="all" 时 hallId 传 undefined。
- **App.tsx**: 新增 `currentStageSteps` state；pollingTasks 增加 `currentStageConstructProcess` 任务；两处 `<ConstructFloatCards>` 传入 `steps={currentStageSteps}`。
- **ConstructFloatCards.tsx**: 接收 `steps?: unknown` prop；`normalizeSteps()` 容错解析（数组/data/rows/list + title/name/stepName + completion/commence），无数据时回退默认 PROCESS_STEPS。
- **接口实际返回**: `data: [{ name, completion, commence, hallId, hallName, ... }]`，按数组顺序渲染为 Steps 1/2/3/4，标题取 `name`（用户不要 completion/commence 数量显示，已移除）。
- **注意**: 用户明确要求接口数据动态替换写死的 PROCESS_STEPS，不要添加额外的数量显示。
- **关键bug**: `useSequentialApiPolling` 配置 `immediate: false`，首次不会立即拉取 → `currentStageSteps` 初始 null → 组件回退写死 PROCESS_STEPS。**修复**: 在 loadAll（切换模块立即加载，useEffect 依赖 `[hallMode, selectedHallId, isInitialLoading]`）的 ConstructOverview 分支中也加入 `getCurrentStageConstructProcess` 请求并 setCurrentStageSteps。这是本项目所有"首次加载数据"依赖 loadAll 而非 polling 的模式。
